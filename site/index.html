Let nothing finish until your own checks pass.

detent dispatches Claude Code at a queue of tasks, one at a time. It holds each one behind the repository's own gauge on the way out, has a second model read every green diff, merges what survives into a branch of its own, and writes down what each run cost in attempts, time and money.

A detent is the catch that holds a mechanism in a defined position until it is deliberately released. Here it is released by a green gauge, and by nothing else.

The three claims

The constraints are in the code, not in the prompt.

When is the agent allowed to stop?

When the project's checks pass, not when it says it is done. Red means it does not get to leave, and it is handed the failure text to work from.

Was it worth it?

Every run is a line in a journal: which model, how many rounds, which stage it died on, how long, how much. "Which model should run this repository" becomes a number.

Who says it is done?

A second model reads the diff against the acceptance criteria. It may demote, never approve. Green is granted by machine checks only.

How a run goes

A task is a markdown file, and only its body reaches the agent. Up to attempts rounds (three by default), each one spent the same way whether the gauge was red or the reviewer had a doubt.

lets it throughcosts a roundstops and asks a person

Every run leaves one line in runs/journal.jsonl: outcome, rounds, the stage it died on, the model that actually ran, and what it cost. The dashboard and detent summary are computed from that file and nothing else.

The line agents do not cross

detent reads and writes refs under refs/heads/agent/ and nothing else. Both gates between the two territories are human operations, in both directions.

It refuses to start on a dirty tree, and never moves a ref outside its own namespace. Nothing in a repository of your product is ever pushed by it, not agent/dev and not a tag.

Watch a run in the dashboard

A task is the prompt

The frontmatter is bookkeeping. The spec written before the work is what the agent gets.

---
id: 0001
repo: acme-api
touches_contract: false
---

# Goal

One paragraph: what must work when this is done.

# Acceptance criteria

- [ ] a checkable statement

# Out of scope

What not to do while you are in there.

detent runwork the queue
detent promotemerge agent/dev into agent/staging behind the batch gauge
detent summarypass rate, rounds, cost per pass

detent gaugerun a repository's gauge by hand
